# Запуск нового чата: Фаворит 2.0, зимний быстрый режим

Дата: 19.11.2026. **Назначение:** стартовая краткая инструкция для нового чата, чтобы не перечитывать прежний длинный диалог.

## Приоритеты
1. **Точность и скорость:** целевой пользовательский замер — не более **90 секунд от отправки полного комплекта до появления PDF**. Не гарантировать это время заранее.
2. **Основной ввод — фотографии и направление/СТС**, диктовка не обязательна. Когда пользователь передаёт фото и явно просит акт сразу, готовить его без дополнительных согласований, но сначала **внутренне** составить нумерованный перечень. При отсутствии разрешения на немедленную сборку показать краткий список и получить «собирай».
3. **Один проход по исходникам:** реквизиты и фото → два независимых списка «ДТП» и «эксплуатационные» → заполненный блок входных данных → генерация → машинный контроль и **один** визуальный обзор → PDF. Без промежуточных отчетов, повторного OCR всех страниц, лишних монтажных изображений, множества конвертаций и обновления базы до выдачи результата.
4. **Не угадывать:** тип страхования, номер убытка, ремонтные воздействия, VIN, сторону, подписи, состояние «на ходу», принадлежность старых дефектов. Если факт не установлен — оставить неизвестным или отметить ограничение. Тестовый PDF не выдавать за действующий.
5. **Стороны по ходу движения**, минимум два независимых ориентира. Сопряжённые элементы и внутренние части проверить по имеющимся фото; не объявлять скрытые повреждения установленными. Особенно проверять: фары и крепления, подкрылки, спойлеры/накладки, два отражателя/фонаря номера, нижние/силовые детали. Дефекты эксплуатации искать отдельным обходом всех 4 сторон.
6. **Перед каждой новой сборкой читать актуальные** `favorit-2.0/PROMPT.md` и `favorit-2.0/Favorit_AKT_autonomous.js` из **GitHub main**, не старую копию. Одним параллельным запросом получить другие нужные короткие инструкции/справочник. Использовать автономный JS: новый бланк, подпись и XML-разметка уже внутри него; отдельные DOCX/PNG/TXT/`podpis.js` не нужны. Не менять рабочий генератор: только входной блок `const D` и сопровождающие переменные до отметки «Конец блока данных». Не проводить самостоятельный рефакторинг во время осмотра.
7. **Страховые не смешивать:** для Фаворита бланк от 18.11.2026, для ЛАТ АССИСТАНС прежний отдельный бланк. Общая экспертная методика подходит всем, правила формы различаются.
8. **Контроль PDF:** точный номер убытка на каждом листе, 17 символов VIN, стороны и перечень, галочки, подписи, перечень начинается с листа 3, текст без наложений; для КАСКО ремонтные воздействия только при обосновании. Если ошибка — исправить и только потом выдавать. Тест с неполными данными под `AKT_TEST=1` не считать готовым реальным актом.
9. **Никаких GitHub-коммитов в горячем пути сборки.** При сравнении с контрольным актом в другой задаче записывать исправления в `knowledge/CORRECTIONS.md`. Во время срочного акта только читать, строить и отдавать.
10. **Скорость:** времена Node/LibreOffice 3–6 секунд измеряли, но это не весь цикл. Реальные пользовательские замеры из предыдущего чата: повторные Vesta 59 секунд, Granta 62 секунды; новый Lifan 123 секунды, новая Granta 225 секунд. Эти цифры нельзя обобщать как гарантированную производительность. Время старта сообщения и доставки ответа обычно недоступно модели; пользователь измеряет на клиенте. По возможности замерять этапы инструментально, без удлинения процесса лишними вызовами.

- `favorit-2.0/New_Favorit_AKT_refined.js` — резервный предыдущий генератор, использовать лишь при явно согласованном откате.

- `favorit-2.0/knowledge/CORRECTIONS.md` — уроки прошлых ошибок.
- `favorit-2.0/knowledge/FAST_MODE.md` — технический быстрый маршрут.
- `favorit-2.0/tools/fast_build.py` — единый сборщик с машинным контролем.
